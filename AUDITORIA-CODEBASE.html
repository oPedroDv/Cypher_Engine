4. Problemas CRÍTICOS

4.1 API Key ignora todos os scopes de autorização

Severidade: CRÍTICO · Plano: Onda 0 #4

Arquivo: RequiresScope.java (L13); ApiKeyAuthentication.java (L21–22)

Descrição: @RequiresScope autoriza SCOPE_{value} ou ROLE_API_CLIENT. Toda API key recebe ROLE_API_CLIENT sem scopes granulares.

Impacto: Comprometimento total do tenant via uma única key.

Corrigir: Persistir scopes em api_keys; remover bypass ROLE_API_CLIENT.

Esforço: M

4.2 Endpoints de company/statistics sem controle de scope

Severidade: CRÍTICO · Plano: Onda 0 #5

Arquivo: CompanyController.java (L22–50); StatisticsController.java (L21–24)

Descrição: Só exigem autenticação; JWT sem scopes adequados ainda acessa perfil, refresh e estatísticas.

Impacto: Escalação de privilégio dentro do tenant; abuso de cotas externas.

Corrigir: Anotar com @RequiresScope; rate-limit em refresh.

Esforço: S

4.3 Swagger / OpenAPI públicos em produção

Severidade: CRÍTICO · Plano: Onda 0 #3

Arquivo: SecurityConfig.java (L48–55)

Descrição: /v3/api-docs/** e /swagger-ui/** em PUBLIC_ENDPOINTS sem perfil dev.

Impacto: Reconhecimento ofensivo; documentação pública da superfície da API.

Corrigir: Restringir a dev/local ou exigir autenticação.

Esforço: S

4.4 Credenciais de banco hardcoded como default

Severidade: CRÍTICO · Plano: Onda 0 #1

Arquivo: application.properties (L1–3)

Descrição: username=postgres / password=postgres sem env obrigatório.

Impacto: Acesso total ao PostgreSQL em deploy mal configurado.

Corrigir: Exigir DB_USER/DB_PASSWORD sem default; fail-fast no boot.

Esforço: S
